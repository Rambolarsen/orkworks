## Investigated uncertainty and boundaries

The baseline approved-plan list is prose, not a selected canonical source envelope.
The accepted nested source grammars explicitly close root-only permissions/settings/
assignment/rendering. They cannot be reused as complete child sources by changing a
role label. The new proposal therefore chooses a bounded one-task/no-live-access
child slice, explicit child specializations, immutable snapshots and distinct event
records rather than a generic source JSON bag or a fake approved/session boolean.

Source representation is not source event authority. The immutable reservation
must capture the actual normal #742 transition's resulting taskVersion, and unique
attachment must come from the real lineage owner. The proposal does not close all
mutable orchestration state or grant codecs. Missing native control/consumer/atomic
publication remains a no-go even after a record's hash is correct. Artifact read-work
ordering #1184 and other excluded source actions retain their own authority cutoffs.

One root author owns spec/plan and all edits. After drafting, two independent
read-only lower-cost reviewers check (1) correctness/accepted-contract compatibility
and (2) unanswered builder/closure decisions. Maximum three active agents, one
bounded review round; no concurrent writers, code, model/native probe or metadata
reporting from reviewers. Apply findings before the written owner-review handoff.

## Gate A — scoped source/profile decision

- [ ] Review the selected single-task/retained-data limits, explicit new child
  leaf/framing/input-delivery and plan/approval/source records/domains, no-pruning
  source resource and fresh preparation order. Confirm no old codec/approval or
  unknown consumer is silently promoted into this slice.
- [ ] Record exact owner acceptance or revisions, and reconcile owning #741/#742/
  #744/#746 catalogs. New source choices are not covered by accepting #1176's
  artifact metadata representation. No dependent source fixture or adapter starts
  merely because this design is merged.

Check: every exact field/tag/domain/bound/command/default and newly excluded profile
has a named choice; no open generic JSON leaf is treated as a source-valid record.

## Gate B — bounded component codecs and source ownership

- [ ] After applicable acceptance, independently pin selected nested child and full
  source object bytes, snapshots, approved plan/approval request/receipt, immutable
  reservation/allocation/attachment and child source reference reconstruction.
  Preserve all older root/child catalogs and source/wire identity mappings.
- [ ] Exercise unknown/duplicate fields, invalid integers/Unicode, wrong root/child/
  profile, mismatched plan/configuration/task/snapshot/result/approval, dirty base,
  source versus allocated worktree substitution, ambiguous original version/child,
  missing source, oversized startup/plan/row/metadata and changed retry. A structural
  unverified source example must never be labeled an eligible native profile.
- [ ] Identify actual source creation owners/entry points for proposal, UI approval,
  reservation, filesystem outcome and lineage attachment. Close every underlying
  mutable source/control record, fresh root/run/parent state and dependency/index
  expansion used by those transitions before claiming complete source prestate.
- [ ] Establish current native authority and workspace/lease/source fences for
  excluded source metadata actions; no artifact-write claim, response precheck or
  core-lock-through-fsync workaround. Any required new policy is reviewed separately.

Check: byte/component evidence is scoped correctly; actual source event proof and
complete underlying control/consumer/authority evidence remain distinguishable.

## Gate C — complete fresh preparation/publication witnesses

- [ ] Only when preceding source/authority choices and owners are closed, generate
  complete before/after source/control/lineage/dependency/summary/quota/index rows
  and manifests for every source action. No omitted symbolic control side, missing
  zero row, presumed fresh owner or high-water reconstruction.
- [ ] Cover shared workspace/run usage, duplicate/revoked/stale retries, interrupted
  allocation and attachment, held history/proofs, source/row/command/query/whole-store
  budget denial, lost responses, source health and no-pruning saturation. Reconcile
  all six target/artifact resources and exact owner mapping without resetting peers.
- [ ] Join child source to accepted artifact metadata/evaluation/receipt/custody
  effects only after both source and artifact gates hold. Preserve detail-only
  snapshot invalidation, historical identities and protected paired credits.

Check: independent state/diff/commitment and conservative maximum-width packing or
explicit denial, not isolated arithmetic or staged captured context posing as SQL.

## Gate D — separately approved executable qualification

Only after the relevant written decisions, prepare a bounded actual implementation/
platform plan with module owners, supported versions, private disposable stores,
finite fault/sample/time budgets and cleanup. Observe real atomicity, native object
identity, memory/worker/lease/authority/stop responsiveness and capability evidence.
#740, #1184, #745 shared custody and maximal profile gates remain independent.
No migration/rollout/reversal mechanism is selected here; code has not started.

## Risk and review disposition

Dependencies 4 (three source owners, lineage, storage and authority); blast radius 4
(cross-run protected source/consumer membership); state changes 3 (proposed additive
new-store source records, no old-store import); reversibility Unknown (no executable
migration/rollback evidence); uncertainty 4 (underlying control/native cutoff still
unqualified). Sum incomplete. Ratings are not acceptance thresholds.

One bounded read-only correctness and builder review round identified an incorrect
ParentPlanBinding field count, the reviewer delivery-order bound and an invented
inherited root permission-fixture type. The author corrected the count to ten,
selected worker 1–33 / reviewer 2–34 delivery entries with immediate post-supplied
input ordering, and retained exact bounded evidence bytes without claiming a
closed permission-fixture type or a passing check. Reviewers reported no other
material findings; this was one round, not an independent post-edit review.

Disposition: **Investigate for full source/executable qualification; ready for
written owner review of the named new choices.** No acceptance or native result
is inferred from the review or documentation checks.
