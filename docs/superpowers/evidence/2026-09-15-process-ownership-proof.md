# Process ownership proof — Task 7 evidence and status

Status: fix round 1 evidence consolidation; issue #545 remains open.

This record consolidates the fixture and production-seam evidence from Tasks
1–6. It is evidence only: it does not implement runtime recovery,
multi-workspace replacement, a production supervisor, or an ADR decision.

## Outcome

The fixture has a complete 48-row matrix: 16 required scenarios × Windows,
macOS, and portable Linux. The validator requires every scenario/platform row,
the exact aggregate totals, non-empty `evidence_ref` values, and concrete
reasons for unresolved/unsupported rows. It also requires every `pass` to
name independent observation and forced-parent proof.

- **5 pass rows:** Windows Job Object native fixture rows.
- **9 accepted rows:** platform-neutral protocol or fixture-contract evidence;
  these are not native containment passes.
- **1 unresolved row:** macOS production launch-seam audit.
- **33 unsupported rows:** unavailable native runtime, rejected macOS launch
  path, or unrun platform-specific coverage.

## Native and fixture findings

Windows is the only demonstrated native ownership mechanism. Hosted GitHub
Actions run `34995897012` executed the exact `windows_job` command on
Windows Server 2025 x64 MSVC and passed all 8/8 tests. Those tests cover
suspended registration, Job Object kill-on-close, PTY-like and nested
descendants, breakaway rejection, non-inheritable handles, registration
failure, and actual `TerminateProcess` parent termination. The fixture
proves the Windows mechanism for its topology; it does not prove production
routing or Unix behavior.

Task 4's macOS candidate matrix is vacuous/re-scoped for ownership proof:
the six candidate tests pass by rejecting ProcessGroup, RegisteredRoot, and
launchd before native target launch. They do not exercise the required
setsid/new-group/daemonized/reparented descendant matrix or a launchd
bootstrap/bootout lifecycle. Candidate labels remain descriptive of the
candidate under test; they must not be read as a generic Unix ownership
selection.

The admission-substitution isolation/reliability evidence is also bounded:
the fixture covers verified-image/path-substitution and sibling-descriptor
isolation checks, but the macOS host cannot run the positive descriptor launch
path and no portable Linux descriptor runtime result was produced here. The
missing Linux descriptor runtime evidence remains a blocker, not a pass
inferred from source checks or macOS fail-closed behavior.

Task 5's macOS run passed 47 fixture integration tests, with 4 applicable
tests and 14 launch-dependent tests skipped. Its parked acknowledgement-
concurrency gap remains open. The serialized paused-launch latch test is
preserved, but it does not by itself prove that cleanup acknowledgement is
serialized against every in-flight paused launch, so this record does not
claim that proof is closed. The escaped-JSON 64 KiB framing gap also remains
open: bounds were checked before final JSON escaping and escaped-identity
coverage is still missing. The foreign-owner helper uses a heartbeat thread,
not an independent scheduler process, and the compatibility adapter cannot
forcibly cancel an arbitrary blocking external adapter call; both remain
fixture qualifications.

No native Linux runtime was available in this checkout. Linux rows therefore
remain unsupported; no Linux result is inferred from macOS or Windows.
