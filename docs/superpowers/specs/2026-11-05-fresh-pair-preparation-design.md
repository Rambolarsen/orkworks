# Fresh pair initialization and original child preparation contract

Tracking: [#1438](https://github.com/Rambolarsen/orkworks/issues/1438),
[#1176](https://github.com/Rambolarsen/orkworks/issues/1176), initiative
[#738](https://github.com/Rambolarsen/orkworks/issues/738).
Inspection base: `51ab79fe82f3f695ac3b97e9f59fcd896dd820e5`.

## Outcome and proposed scope

Close the next finite contract identified by the
[source-publisher readiness checklist](2026-11-05-source-publisher-execution-design.md#finite-implementation-readiness-checklist):
one genuinely fresh ordinary schema2/hierarchy format6 pair, the original
root/parent/direct-execution events needed to establish a child prestate, and
one original child-source-attach. This is a contract proposal, not an executable
plan, initialized store, admitted source or complete-state fixture.

Reuse the accepted broker, lineage/tombstone, exact preparation permit/evidence,
physical membership and RegistryRoot decisions. The author proposes the exact
fresh resource seed schedule and original parent-attach command classification
below. No new resource name, numerical allowance, source/request/receipt codec,
ordinary member, commitment domain, capability or second-attempt permission.
All unrelated resume/spawn/ending/coordination/recovery events remain gated.

The selected path uses the accepted single-task-retained-data-execution-v1
profile, an original current parent and its first direct execution proposal.
Known clarification/research needs or unsupported input variants deny this path.
A reviewer additionally needs its exact already-retained target/result/evidence
source group; this proposal does not manufacture that target history or authorize
its producing commands. Existing ordinary stores or previously occupied pair
paths require their separately approved transition; they cannot use fresh seeding.

## Private inputs and disposition

The paired storage module accepts typed source-command plans from their original
owners, never arbitrary SQL/table/key/value lists, serialized grants, supplied
absence booleans or a caller-selected affected set. The types here describe its
private seam; none is a new wire or persisted command envelope.

| Private operation | Complete input and owning basis | Disposition |
| --- | --- | --- |
| initialize_fresh_pair | Owned selected workspace/lease and reserved original native file/directory identities, qualified fresh storageEpoch and ordinary UUID epoch, and the exact frozen seed/catalog plan below | Original proven joint outcome or retained unknown; no live source/runtime capability |
| prepare_root_draft / admit_root | Existing exact RootPreparationDraftV1/approval request and retained original review context, burned namespace/run/parent reservation, source bytes/artifacts and complete old/new plan | Existing root source/receipt plus seeded controls/resources only after original proven commit |
| attach_original_parent | Exact original root source and reserved parent, actual originally authorized ordinary runtime/native outcome, its unchanged approved startup/configuration, RuntimeAttachmentV1 and coherent H/G/control read set | Original immutable parent runtime history and current pointer, never process adoption or spawn authority |
| propose / approve / reserve | Existing exact accepted source requests/records and original current parent/UI/grant owner, complete controls/membership/resource reads | Existing original source/control outcomes, without caller authority inferred from retained bytes |
| allocate_original_begin / allocate_original_outcome | Original reservation/admission, exact private allocator plan and actual original native outcome; retained TaskKey/configuration/plan/worktree joins | Allocating intent, then verified allocation or retained interrupted/unknown state; never a second attempt |
| prepare_original_child | Exact full P, derived attachment/source, ordinary normalized creating record/creation identity, OriginalPreparationIntentV1, frozen complete effect plan and actual original permit owner | Original PreparedChild only after complete paired commit and ordered publication; no SessionHandle/startup/grant |

Owned workspace, native reservation, live parent/grant, allocator outcome and
permit are non-forgeable private owner references, not bytes accepted as proof.
Their constructors and actual producer paths are still unqualified. Captures
bind both epochs, exact H/G, actual paired connection generation and full read set.
A historical source codec or pure validator cannot construct these inputs.

Every attempt has exactly one frozen plan and one sole active-or-retiring
position. Pre-admission denial has no durable effect. Proven rollback retains
complete old state; consumed volatile permit sequence is never reused. Proven
commit/lost response resolves the exact original retained result under current
lookup authority, with no new C/G, initialization, version, charge or grant.
Unknown retains original plan/worker/lease/paired resources until the same owner
proves complete old/new disposition; timeout, task Drop or interrupt is no proof.
A new process recovers data only, never the volatile plan/permit or a new attempt.

## Fresh pair initialization

This selected initializer is for **both files genuinely new and owned**. Require
an explicit authorized preparation operation under the original selected lease,
qualified fresh epochs and native exclusive ownership. Absence of a pathname,
missing peer/header, empty table, deleted marker or maximum sequence is not that
proof. Reserve both original files before publication and retain their exact
native identities through initialization/disposition. No initializer can adopt
an existing ordinary schema1/schema2 or hierarchy file, including a partial fixture.

Use the accepted one ordinary-worker connection with ordinary main and one
verified hierarchy peer, persistent rollback DELETE/EXTRA and the accepted shared
journal/scratch bounds. Define both complete catalogs and initial state in the
same original transaction before exposing any initialized-pair result. Native
file creation, directory durability and pair ownership are separate prerequisites
of the qualified initializer; this document supplies no filesystem protocol or
claim that SQL rollback undoes file creation. A failed/unknown creation leaves
that original attempt unavailable; do not delete/recreate files or mint epochs.

The ordinary header is schema2 with the qualified ordinary epoch, history
G="0" and null import digest, and no sessions, organization, search, lineage or
delete jobs. Its schema2 lineage index is present even when empty. Do not write
an ordinary activation marker or select SQL production from this operation;
ordinary producer/cutover ownership remains [#1242](https://github.com/Rambolarsen/orkworks/issues/1242)
and [#1244](https://github.com/Rambolarsen/orkworks/issues/1244).

The hierarchy catalog is the accepted complete 35-family profile plus its fixed
physical structures/indexes. Its first manifest is schemaVersion6,
commandKind initialize-store, claim null, commitSequence "1", predecessor null.
Propose these **thirteen** workspace quota_usage keys, each under exactly
`{kind:"workspace",workspaceId}`, all used="0"/reserved="0":

| Resource group | Exact resource names |
| --- | --- |
| Subject/reporting/artifact | reporting-receipt-bytes, assignment-record-bytes, result-payload-bytes, evaluation-artifact-bytes, evaluation-artifact-read-bytes |
| Summary | summary-row-bytes, summary-row-count, summary-lineage-bytes, summary-pending-count |
| Root preparation | preparation-retained-bytes, preparation-run-count |
| Child metadata | child-source-retained-bytes, child-control-retained-bytes |

This extends the [older nine-resource initializer](2026-10-28-root-preparation-effects-design.md#resource-keys-and-zero-initialization)
for this one fresh format6 profile by four already accepted resources: two
artifact resources and the child source/control pools. It is not missing-row
repair or permission to extend an old store. The thirteen inserts are exactly
its logical changes; header/new proof use their separate equations, giving fifteen
initial hierarchy logical rows. No run/subject/source/control/body/lineage/authorization row
exists yet. Physical owner stamps, full derived memberships and index state must
correspond exactly to these initial rows and empty remaining families, including
the special header/manifest stamps; they are additional physical work, not extra
logical changes or free copies.

Compute all row commitments under the accepted format6 projection, hash the
complete sorted initialization manifest, then attach only named excluded C links.
The earlier header-only golden and nine-row source packet stay unchanged. A
second null predecessor, unknown resource or any extra/missing initial row denies.
No root admission, ordinary parent creation, grant or runtime starts in this C.

## Root and original parent establish the prestate

Fresh initialization is not root preparation. Preserve the existing separate
root-draft-prepare, root-draft-cancel and subject-preparation operations and their
UI/source authority cutoffs. Their complete source bytes, receipts, artifacts,
quota effects and summary branches retain their accepted codecs and joins.

1. The namespace owner burns the original run/parent reservation before draft
   publication. Draft preparation inserts the exact draft/artifacts and its
   run preparation-retained-bytes row with actual used bytes, coalescing workspace
   preparation bytes/run-count. Denial cannot unburn the reservation. No ordinary
   parent, run source/current control or subject is created by a draft.
2. Exact root admission consumes that draft, retains original root source/receipt,
   initial run_states and reserved parent_attachments, and creates the root's
   exact summary branch. Preserve artifact occurrences and charges. Its original
   root assignment receives only the three already accepted zero reporting/
   record/payload rows; root artifact production remains unsupported.
3. In the same root admission, propose seeding the run's five shared subject/
   reporting/artifact resources and child-source-retained-bytes at zero. Seed
   child-control-retained-bytes with the exact charge for the initial run control.
   The run preparation-byte key already exists from its draft and is replaced
   only by its actual old-to-final delta. Thus eight named run resources exist
   before a child proposal; none is initialized on later source actions.
4. Co-publish ChildRunControlV1 at runVersion 1/state assessing from that exact
   root/bootstrap/run/repository/source binding, parentRuntime/currentInput/
   currentPlan/pendingPlan null, planReferences/blockers empty,
   stageContinueRequired false and pendingClarification/pauseReason/resumeTarget
   null. No plan/task/launch/session/runtime history is seeded. Charge its full
   control wrapper and all actual root/summary/physical effects; recompute the
   complete manifest instead of reusing the older root packet's row count.

Propose one narrowly closed new manifest commandKind **parent-runtime-attach**
for the first original successful parent attachment only, with manifest claim
null and the ordinary predecessor/successor proof equations. Its private input is
the original root/reserved parent plus actual authorized native/ordinary producer
outcome, not a supplied RuntimeRef. At one H/G and actual current source cutoff:

- Replace only that parent's reserved parent_attachments with its accepted
  attached variant, insert the exact immutable parent RuntimeAttachmentV1, and
  set the initial current run's parentRuntime with runVersion 1→2. Preserve the
  historical run_states seed and root receipt/source.
- Preserve ordinary creation/runtime identity and prove the actual current
  runtime through its producer; no existing process/session/path is adopted.
  The ordinary producer owns its real metadata publication. This event does not
  create an ordinary child lineage member or pretend SQL starts a process.
- Apply exact preparation/control retained-byte deltas and full physical owner/
  edge/identity-contributor changes in the original owning transaction. No grant,
  child, assignment source or evaluation is created. No #744/debit/preparation
  permit authorizes this strict-cutoff event.

This adds no parent source field or runtime domain. It closes the command
classification previously missing from the event inventory, only for first
attachment. Parent resume/replacement, unsupported startup or any ambiguity
remains unavailable under separate event/cutoff qualification.

## Original direct-execution path to allocated

Use the [five accepted source commands](2026-10-31-child-review-source-preparation-design.md#five-accepted-command-kinds)
and [control transitions](2026-11-02-child-launch-control-design.md#transition-and-recovery-rules)
without adding a generic control-write command. Each phase captures/revalidates
its complete original source/parent/control/membership/proof/resource read set;
all real producers and strict source cutoffs remain unqualified prerequisites.

| Event | Required original prestate and exact outcome |
| --- | --- |
| child-source-propose | Current original parent in assessing/current permitted state, no unsupported blockers or clarification/research need. Freeze exact prepared input before new plan digest; insert complete original plan/configuration/evidence/input/provenance and new plan/task controls at version 1. Update currentInput/ordered planReferences/pendingPlan and actual run state/version once. Source/control run/workspace pools already exist and pay every occurrence |
| child-source-plan-approve | Exact retained shown-byte context/UI and original plan/input/configuration. Insert original approval source/receipt, activate that plan and update actual run/plan fields/versions once; preserve historical sources. Only a separately qualified eligible unreserved-task authority may create a volatile exact-plan grant |
| child-source-reserve | Exact actual current parent/grant, approved plan/group/input, pending task and complete capacity/absence. Commit original reservation and launch admission at phase reserved, task launching and one checked taskVersion advance, frozen as assignmentTaskVersion. No native mutation |
| child-source-allocate: private Begin | Original reserved attempt with null allocation/attachment/runtime, exact unchanged allocator plan from the immutable approved group. Persist phase allocating before native effects, advancing the relevant live taskVersion once; preserve frozen admission. Same command tag, no new persisted phase envelope |
| child-source-allocate: private Outcome | Same original allocating attempt and retained private plan. Actual original native success inserts ChildAllocationSourceV1 and sets allocated with original AllocationRef/observedDirectories; advance relevant live taskVersion once. Failure records exact accepted interrupted stage/reason/observations and task launch_interrupted, retaining attempt/capacity; unknown is never inferred success |

Begin and Outcome are distinct private typed operations under the existing
child-source-allocate tag, not one transaction spanning filesystem work. The
frozen private native plan retains all original object/path/branch/operation
identities; it cannot be recomputed into a second allocation. Process loss without
qualified original native disposition leaves allocating/interrupted unavailable.
A surviving directory or source success codec cannot recover missing ownership.
No automatic outcome publication/retry or new allocation is authorized here.

This path requires the exact supported original run/plan/task semantic transitions;
source commands cannot rewrite unrelated controls or stamp read-only peers.
Overflow denies; no live task version is recaptured into P. No standalone input
publisher, replacement plan, resume, spawn or recovery event is supplied.

## Exact original child-source-attach

The admitted prestate is the complete original executing run/active plan/task
launching, allocated launch with null attachment/spawnRuntime and no interrupted/
unknown outcome. The original reservation/allocation and frozen P/configuration/
input/approval agree; actual original parent/source authority still exists.
Require full session/attachment/tombstone uniqueness, absence of original child
preparation/subject/assignment resources, all ten five-resource peer keys and both
source/control run/workspace pools, complete bounded membership and H/G/read set.
Use exact identity bindings/ordinary occupancy, not an absence flag or table count.

The source/ordinary owners prebuild the exact normalized ordinary creating record
and creation identity, attachment/source, complete old/new effects, original four
control snapshots, candidate permit body/digest and all copied-byte/physical
charges. The short shared cutoff compares/consumes the exact candidate sequence
and retained source state and freezes that whole immutable plan. A stale candidate
or revoke-first admits no write; hashing/copying and all SQL run outside core latches.

The one transaction has exactly this supported logical effect recipe, plus its
actual coalesced quota and separate header/proof controls:

- Insert ordinary canonical creating metadata/revision, history/search projections,
  immutable schema2 member/full-P index; advance G once. No SessionHandle/startup.
- Insert original child_attachments and child-assignment-source object with its
  exact prescribed provenance dependencies. Retain original approval/reservation/
  allocation; no rewriting those immutable rows.
- Replace allocated launch with prepared, setting original attachmentId and
  retaining allocation/frozen admission/observations and null spawnRuntime. Insert
  ChildSessionStateV1 at producerRevision "1", state prepared/runtime null. Advance
  live ChildTaskControlV1.taskVersion once for this relevant launch/session event;
  retain task status launching/reservation and null coordinationResult. Plan/run
  controls remain read-only when none of their semantic fields change; no extra
  control increment is added merely to store the authorization.
- Insert the accepted initialized Unassessed/checkpoint summary branch at
  subjectRevision "1", or the never-initialized null marker if only summary
  capacity is denied and the complete remaining command fits. No pending material.
- Insert exactly five assignment quota keys for the new P at used="0"/reserved="0".
  Ten corresponding run/workspace peers already reconcile and stay unchanged merely
  because P is new. Apply actual source/control/summary deltas without borrowing
  these zero ledgers or rewriting unchanged links.
- Insert ordinary_child_lineage and one immutable child_preparation_authorizations
  row; maintain exact permit/session/attachment/lineage bindings, contributors,
  full forward/reverse/direct memberships and all ordinary projections atomically.
  No artifact_read_metadata is created without an actual artifact publication.

Compute source/attachment and authorization digests, all charges/row commitments,
then the complete format6 manifest C with claim null/commandKind child-source-attach,
predecessor H and checked successor sequence. Attach only existing excluded links
at their named paths. The lineage preparationCommit, immutable source/attachment
owning links and authorization.lastCommit equal original C; every snapshot origin
and expected H remain hashed and retained. All physical projection deltas count
actual copies/index work even though they add no logical manifest family.

Only proven joint commit plus ordered reference publication returns the exact
original PreparedChild. Permit-first may save this one complete unstarted outcome
after later volatile close; it never excuses actual lease loss, H/G/read drift,
quota/health/profile failure or a second SQL attempt. Retain original unstarted
history/charges and count prepared child instead of its reservation once. Closed
authorities remain closed. Exact retry returns original P/C/creation identity,
never rewrites later ordinary metadata or creates a permit/grant/spawn.

## Compatibility, denial and remaining evidence

These choices complete only a proposed new-store format6 command/initialization
contract while that profile is still unqualified. Existing command/row domains,
manifest field shape, source codecs, ordinary schema2 member and limits stay
unchanged. The new parent-runtime-attach tag and selected seed schedule require
one scoped decision before dependent fixtures/code. No alternate format6 catalog,
old-file import or reader normalization is permitted; a reader lacking any required
command/variant or exact physical layout refuses the profile before admission.
Any later incompatible qualified/deployed profile needs its own version decision.

All complete command/discovery/ordinary job/source/control limits apply, including
1 MiB ordinary joint intent, one hierarchy active-or-retiring position, bounded
queues, full logical store/proof counts, 1 GiB hierarchy file, shared 2 GiB rollback/
auxiliary total and 8 MiB SQL scratch. No maximum-width fit is claimed. Initial
zero ledgers, owner stamps, retained roots/plans, tombstones and unknown completion
consume their real limits; denial cannot produce a partial seed or clean-up refund.

Required later oracles: exact 13-key empty seed versus missing/extra keys; occupied/
one-sided pair refusal; lost-response/unknown original creation; root draft-to-
source transfer and all run/subject key ownership; wrong original parent/native/
source/control/epoch; allocating intent before effects and interrupted outcomes;
complete original attach under both summary branches; stale candidate/H/G/read
set; revoke-first/permit-first; actual lease loss; exact retry with edited display
metadata; corrupt/missing sparse origins/index contributors and no content access
before B. These are acceptance requirements, not generated fixtures or test results.
