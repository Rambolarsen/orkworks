# Legacy adoption inventory and owner confirmation v1

Tracking: [#1500](https://github.com/Rambolarsen/orkworks/issues/1500), parent
[#1244](https://github.com/Rambolarsen/orkworks/issues/1244).
Policy: [accepted additive adoption](2026-11-07-legacy-source-adoption-amendment.md).
Delivery: [qualification step 1](../plans/2026-11-07-legacy-source-adoption-qualification.md).
Source inspection base: `de180b5d685b80329ce808e74147cff9817db609`.

This is a proposed **written logical contract**, not a serializer implementation,
qualified native/backup receipt, approval endpoint or permission to publish files.
The accepted policy is unchanged. Representation and approval ordering must be
reviewed before dependent code; physical ownership, complete on-disk accounting
and interrupted publication remain step 2. No live inputs, native/model probe,
SQL activation or new execution budget is supplied.

## 1. Encoding and identities

`C(x)` is the exact ASCII JSON encoding of the closed arrays below: no whitespace,
BOM, trailing bytes, escaped spellings, objects, numbers or booleans. Values are
arrays, unescaped ASCII strings and `null` only. Tags/enums are literal strings.
Reject wrong array lengths/types, unknown tags/enums and alternate encodings.
This private `las.*.v1` namespace does not change any hierarchy/source codec.

| Atom | Exact meaning |
| --- | --- |
| `U` | String `"0"` or `[1-9][0-9]*`, checked at most `18446744073709551615`; checked arithmetic, no wrap, saturation or floating conversion. |
| `X` | Even-length lowercase hexadecimal string for exact bytes; empty allowed only where the owning field permits it. |
| `D` | Exactly 64 lowercase hex characters: SHA-256 of the specified exact bytes, without a display prefix. |
| `N` | Exactly 32 lowercase hex characters from a fresh owner-generated 16-byte nonzero nonce; fail closed on generation failure. |
| `Opt(T)` | `null` or exactly `T`; `null` means absent only where permitted, never unknown success. |
| `Unknown` | `["unknown",code]`, where code is from the diagnostic vocabulary below. It cannot satisfy a required binding. |

`H(x) = SHA256(C(x))`. The first tag in each hashable record supplies its domain;
do not substitute a filename, display JSON or a hash from another record type.
Retain and validate referenced full bodies and keys; a matching digest is neither
body availability nor native/owner authority.

`Session = ["las.session.v1",idX,createdAtX]`: strict UTF-8 bytes of the ID and
**exact** `created_at` string, no time parsing/reformatting. Require a nonempty
created value and the current organization owner's ID grammar (1–256 ASCII
alphanumeric, `-`, `_`), with basename/ID agreement for supported metadata.
This follows [`OrganizationStore`](../../../crates/orkworksd/src/session_archive.rs)
creation matching; it is not a filename-only or mtime identity. Unsupported or
unprovable creation identity cannot become an adoptable candidate.

`Profile = [profileIdX,versionU,contractDigestD]` names a closed producer contract,
not a caller-selected plug-in. A maintenance-owner registry must recognize and
validate that exact profile before any evidence can be `known`. Unknown versions
or missing qualification yield `Unknown`; a hash of a profile document alone
never registers it. No production profile is qualified by this document.

`Native = ["native",Profile,encoding,locatorX,identityX]` or `Unknown`.
`encoding` is exactly `posix-bytes` or `windows-u16le`; the latter is an even
number of bytes. The profile defines canonical rooted locator, actual native
identity and revalidation semantics; empty identity/locator is invalid. Paths
preserve native bytes, not lossy UTF-8. `Path` is a nonempty array of nonempty
component `X` values in the selected root's encoding. Reject separator, NUL,
`.`/`..`, rooted/drive-bearing components, escaping redirects and semantic aliases
according to the qualified profile. Equal display paths do not prove identity.

`Receipt = ["known",kind,Profile,idX,bodyDigestD]` or `Unknown`; kind is exactly
`tree`, `scope`, `normalization`, `association`, `history`, `protection`, `quiescence`,
`backup` or `application`. The issuing owner retains the full versioned body and
validates its root/attempt/scope and current applicability. Receipts of another
kind are not interchangeable. A fixture profile or caller-supplied ID/digest
cannot produce a `known` runtime receipt.

`Attempt = [ownerInstanceN,attemptN]` is generated by the maintenance owner.
It is never restored from a report or chosen by an agent. All snapshots,
receipts, review state and confirmation are scoped to this exact attempt and
selected workspace. Format-2/staging evidence and initial-import eligibility
are checked through the existing maintenance owner, not a JSON boolean.

## 2. Complete inventories and snapshot

Capture source and global roots separately. Under the selected source, inventory
supported session/payload inputs and declared evidence-only entries; under the
global root, use the complete backup/import owner's scope. Required exclusions
(credentials, locks, transient relays and native/repository stores) are declared
by the backup profile and represented as exclusions without reading their secret
contents. Unexpected paths are reported, not silently adopted. A scope/profile
that cannot establish complete enumeration and exclusions is unavailable.

An inventory stream starts with exactly:

```text
["las.header.v1",kind,Attempt,rootNative,treeReceipt,scopeReceipt]
```

`kind` is `source` or `global`. `treeReceipt` is kind `tree`; `scopeReceipt` is
kind `scope` and describes the capture/exclusion contract, not successful backup
of this as-yet-unhashed inventory. It must not contain a digest cycle. Final
verified backups are bound only in `Snapshot` after inventory capture.

Rows, in ascending component-byte lexicographic order (shorter prefix first), are:

```text
["las.entry.v1",ordinalU,Path,fileKind,native,sizeU,content,metadata,findings]
```

Ordinals start at zero and are contiguous; duplicate native-equivalent keys or
ambiguous aliases block capture. `fileKind` is `file`, `directory`, `other` or
`excluded`. `native` is `Native`. `content` is `["sha256",D]` for readable included
files, `["not-content"]` for directories, or `["excluded",code]` only for an
explicit backup-profile exclusion. Included unreadable files use `Unknown` and
block capture; unknown sizes/identities cannot be represented as zero/empty.
For directories, `sizeU` is exactly `"0"` meaning no copied content by type;
for an excluded file it is the known stat length, not copied/hashed secret bytes.
Other non-regular objects require profile disposition, never following them.
If size/identity cannot be captured, fail capture with the Error record below;
do not fabricate a valid entry with a zero size.

`metadata` is `null` for non-session files, `["invalid",code]` for readable invalid
local metadata, or exactly:

```text
["valid",Session,revisionU,canonicalSizeU,canonicalDigestD,
 normalizationReceipt,historyReceipt,protectionReceipt]
```

The normalized metadata body remains in the owner's captured input, preserving
unknown supported members, effective provenance and checked revision semantics.
`canonicalSizeU <= 1048576` includes the **entire** canonical metadata record,
not a projected row. Raw source size/hash and normalized size/hash are distinct.
Receipt profiles must establish actual normalization and historical/protection
semantics; inventing an outcome or treating missing optional fields as empty
proof is invalid. Global invalid/corrupt metadata blocks the ordinary import.

`findings` is a sorted, duplicate-free array of diagnostic codes. Readable invalid
local bytes may be inventoried as evidence and explicitly excluded when they are
independent of selected data. That is complete *evidence accounting*, not a claim
that their metadata parsed successfully. Any unreadable/enumeration/identity error
or invalid required selected input prevents a complete eligible snapshot.

Terminate every stream with `["las.end.v1",rowCountU,rowBytesU]`. Wire bytes are
`C(header) + LF + C(row0) + LF + ... + C(end) + LF`; `rowBytesU` is the sum of the
row `C` lengths, excluding LFs. The terminal count must equal actual contiguous
rows. `Descriptor = [kind,rowCountU,rowBytesU,streamBytesU,streamDigestD]` binds the
complete stream including header/end/LFs; no digest is stored inside its own
hashed stream. Counters and hashes are checked by a complete streamed reread.
No all-history in-memory array is required or permitted.

`Snapshot` is exactly:

```text
["las.snapshot.v1",Attempt,workspaceNative,sourceDescriptor,globalDescriptor,
 sourceBackup,globalBackup,quiescenceReceipt,applicationReceipt]
```

Backup receipts bind the exact completed inventories and declared exclusions,
root identities and verified backup sets; both must still be valid. Quiescence
binds current and legacy writer resolution, including owner resolution after an
unclean stop. The application receipt identifies the trusted maintenance/review
owner, not an approval already granted. `H(Snapshot)` is the snapshot ID. Retain
all full receipt bodies; `Unknown` permits a blocked diagnostic report only.
Neither a lease, PID, hash, static profile nor a partial backup makes it eligible.

## 3. Candidate and decision accounting

`Ref = [kind,ordinalU,entryDigestD]` binds an actual full inventory row and its
owning descriptor; kind is `source` or `global`. Verify the referenced row, full
path/native key, hash and scope. `Target` is exactly `["present",Ref]`,
`["absent",Path,parentNative,treeReceipt]`, or `["none"]` for non-adoptable evidence.
Absence is established against a complete global tree and captured parent under
maintenance; it is not an unknown lookup or permission to restore a deleted ID.

The candidate stream header is `["las.header.v1","candidates",H(Snapshot)]`.
It uses the same end/descriptor framing. Each row is exactly:

```text
["las.candidate.v1",ordinalU,kind,sourceRef,target,session,class,association,findings]
```

`sourceRef` and `session` are optional; `kind` is `metadata`, `ndjson`, `terminal`,
`terminal-size` or `evidence`. `association` is null for metadata/evidence,
`Unknown` for an unavailable payload relationship, or exactly:

```text
["las.association.v1",Session,payloadKind,metadataRef,requiredness,receipt]
```

`metadataRef` is the actual source/global metadata Ref; `payloadKind` is `ndjson`,
`terminal` or `terminal-size`; `requiredness` is `required` or `optional`.
The kind-`association` receipt validates all these fields and the source/target
payload slot in this snapshot, not just a filename suffix. Missing qualification
is `Unknown`. Required/optional status cannot be supplied by the caller or
inferred from absence. A known association must name the same Session as its
candidate and valid referenced metadata.

Every included source leaf/evidence item appears once, in source-inventory order;
structural directories/profile exclusions contribute to the inventory/scope
accounting, not adoptable content. Add missing-payload rows in ascending `C(Session)` byte order, then kind
order **only for source-associated sessions** where the selected profiles identify
a slot absent both locally and globally. A slot already present globally is
kept through the global inventory even if the source lacks it. Within a session, kind order is `ndjson`, `terminal`, `terminal-size`. Their source is null and findings identify missing required or
optional content. Never enumerate all global history into recovery candidates.
Global-only data is unconditionally kept and accounted by its complete inventory;
it needs no adopt decision and cannot be deleted by this contract. Report its
counts/bytes and present the complete retained baseline through the inventory
pages defined below; an aggregate or candidate-only view is not sufficient.

Classes and allowed final actions are closed:

| Class | Final action | Required semantics |
| --- | --- | --- |
| `keep-metadata` | `keep` | Same proved identity; equal/differing local metadata never replaces global. |
| `keep-payload` | `keep` | Global payload present; equal/different local bytes never replace/concatenate it. |
| `source-session` | `adopt` or `exclude` | Global session absent, valid source identity/history/protection, possible-deleted-history warning required. |
| `source-payload` | `adopt` or `exclude` | Source payload valid, target absent, same creation proved; selected source-only metadata must also be adopted. |
| `exclude-only` | `exclude` | Readable unsupported/malformed/unassociated source or local identity conflict; cannot override global authority. |
| `missing-optional` | `ack-missing` | No bytes are adopted; report history incompleteness. |
| `missing-required` | `exclude` only when its source-only metadata is excluded | Missing bytes cannot satisfy an adopted/global record; exclusion is not permission to import an incomplete selected session. |
| `blocked` | no ready action | Unreadable/incomplete capture, corrupt/unknown global, protection/deletion work, or unavailable required profile. |

Draft action `unresolved` is permitted for a candidate still requiring an owner
choice. A blocked row has draft action `blocked`; neither action is ready.
All other final class/action pairs are exactly the table above. An adopted or
kept-global session's required slot must already exist or have an approved valid
source-payload adoption; it cannot be excluded/acknowledged around. A local same-ID creation conflict makes
all its source metadata/payloads exclude-only; a corrupt/unknown global identity
is blocked, never “absent.” A payload for an excluded source-only session cannot
be adopted. An excluded candidate with unknown creation identity never supplies
identity for another candidate. Adopted historical metadata never creates runtime,
selection, acknowledgement, native resume or inferred terminal outcome.

Decision rows, one for **every** candidate in the same order, are exactly:

```text
["las.decision.v1",candidateOrdinalU,candidateDigestD,action]
```

The decision stream header is `["las.header.v1","decisions",H(Snapshot),candidateDescriptor]`.
Verify every full candidate body, action/class join, dependency and matching
ordinal/digest; missing, duplicate or extra decisions reject the batch. The
candidate descriptor changes on any new late source item; it is not appended to
an already reviewed batch.

`Summary` is a fixed array in this order:

```text
[globalEntriesU,globalFileBytesU,candidatesU,adoptRowsU,keepRowsU,excludeRowsU,
 ackMissingRowsU,blockedRowsU,unresolvedRowsU,selectedRawMetadataBytesU,
 selectedCanonicalMetadataBytesU,selectedPayloadBytesU,excludedSourceBytesU,
 conflictsU,missingRequiredU,missingOptionalU]
```

Derive every counter from complete inventories/candidates/decisions. Every source
item is charged once by its primary row; references do not double-count it.
Global-file bytes include the complete in-scope file set; no row is dropped from
that accounting because it is not a candidate. Metadata raw/canonical bytes and
payload bytes remain separate, and missing/unknown bytes are never zero success.
The six action counters count exactly the respective `adopt`, `keep`, `exclude`,
`ack-missing`, `blocked` and `unresolved` decision rows, so
`candidates = adopt + keep + exclude + ackMissing + blocked + unresolved`.
`conflicts` counts each row containing any of `identity-conflict`, `alias` or
`protection-unknown` once. Missing counters count rows with `required-missing` or
`optional-missing` respectively, even if excluded/acknowledged. Any count/byte overflow blocks the batch.

`Batch = ["las.batch.v1",H(Snapshot),candidateDescriptor,decisionDescriptor,Summary]`.
`H(Batch)` is the exact batch ID. Retain full bodies, not only summaries/hashes.
A ready batch has complete/valid referenced inputs, no blocked/unresolved rows,
all required associations, valid backups/protection/quiescence and exact counters.
Ready also requires the ordinary global import's validation; a corrupt global
record cannot be bypassed by omitting it from recovery candidates. A report of
zero eligible candidates is not permission to bypass ordinary import
or manufacture a successful recovery. The importer still requires all its gates.

## 4. Report pages and exact owner confirmation

The final report has three ordered presentation phases bound to the same full
Batch and Snapshot: **source inventory**, **global inventory**, then **candidate
decisions**. All three must reach their exact terminal page before confirmation.
Global-only data is inspected in its baseline phase without creating an adoption
or deletion decision for it. No phase is replaced by summary counts or hashes.

An inventory page is exactly:

```text
["las.inventory-page.v1",Batch,Snapshot,kind,offsetU,totalU,nextOffset,entries]
```

`kind` is `source` or `global`; entries are contiguous `[Ref,fullEntryRow]` pairs
in that inventory's canonical order. Ref kind/ordinal/digest, full Entry bytes,
header/root/scope and end-count/byte commitments must match the corresponding
Snapshot descriptor and retained full stream. `total` equals that descriptor's
row count. Include every directory, declared exclusion and non-candidate item;
never substitute candidate membership for a complete baseline. Empty inventory
uses exactly one zero-entry terminal page, not an omitted phase.

Inventory pages obey the same inclusive 100-entry and 262144-complete-`C(Page)`
byte limits and longest-prefix/no-truncation/oversized-entry rules as candidate
pages below. Their full Batch/Snapshot context, entries and repeated bytes count
each time; no baseline/reference/duplicate-body byte discount. Inspection is
streamed without retaining all history in memory. Unknown/unreadable scope cannot
be turned into a zero-entry page. A later phase cannot imply an earlier phase
was presented, and only the trusted presenter can record phase completion.

The immutable candidate-decision review page is exactly:

```text
["las.page.v1",Batch,Snapshot,offsetU,totalU,nextOffset,rows]
```

`rows` contains `[candidateRow,decisionRow,entries]` triples. `entries` is the
sorted, duplicate-free array of `[Ref,fullEntryRow]` expansions (kind order
`global`, then `source`, then numeric ordinal; duplicate kind/ordinal rejects) for the source,
present target and association metadata refs used by that candidate. Reject
missing/extra/mismatched expansions. Root native paths, backup IDs, Summary and
all descriptor/envelope bytes are included through the full Snapshot and Batch;
there is no hidden path/context projection added after byte accounting. Raw
metadata/payload/receipt bodies remain inspectable captured evidence, not report
previews or unchecked replacements. A separate content inspection grants no
confirmation authority and must obey its owner's limits.

`total` equals the batch's full candidate count, `offset` starts at zero, and rows
are contiguous. `nextOffset`
is the checked next ordinal string, or null **only** at the exact end. A zero-row
page is valid only for a zero-candidate batch with offset/total `"0"` and null
next. Draft/blocked batches may use these page bytes for diagnostics, but they
cannot create a ready review or approval. Every page repeats the same batch
identity and identical full Batch/Snapshot; validate `H(Snapshot)` against Batch
and reconstruct each stream/row binding before accepting a page. The UI renders
the included Summary and backup/root context before confirmation.

At most **100 rows** and **262144 bytes of complete `C(Page)`**, inclusive. There
is no transport envelope discount, compression/base64 discount or truncation.
Pack the longest contiguous prefix satisfying both bounds. If even one complete
row triple plus full Batch/Snapshot envelope cannot fit, return `entry-too-large`, do not skip/split it,
and block confirmation. Multi-page review must reach the exact terminal page;
a read/page token or the last page alone is not complete review evidence.

The maintenance owner alone maintains these internal states and operations;
names below specify a logical interface, **not** a new HTTP/IPC endpoint:

| Operation/state | Ordering and result |
| --- | --- |
| `beginReview(Batch)` | Revalidate eligibility; create private review state bound to owner instance, Attempt, full batch and ordered page presentation. Generic report/agent capabilities cannot call this authority path. |
| `presentNext(review)` | Trusted application presenter renders exact roots, decoded safe paths, classifications/choices, counters, missing content and possible-deleted-history warning. Record the page's full bytes, phase and ordinal only after presentation succeeds; invalid/lossy/ambiguous native display blocks review. Present every source/global inventory page and then every candidate page; reads/downloads alone do not mark them presented. |
| Change a choice/input | Invalidate this review and any unconsumed approval; build a new batch and review from offset zero. No reviewed prefix survives a changed batch. |
| `confirm(review)` | Only after all three final phases/pages/context were presented, the actual local owner explicitly confirms this exact batch through the trusted application owner. A delayed confirmation callback revalidates owner instance, Attempt, full batch/inputs and presentation completion. Success creates one private approval handle. Repeated callbacks reject `replayed`; no second handle. |
| `cancel(review)` | Idempotently revoke review and unconsumed approval. A late confirmation cannot revive it. |
| `takeApproval(handle,Batch)` | Maintenance owner revalidates all complete input/protection/backup/quiescence bindings and atomically consumes the handle once. Changed inputs reject `stale`; reuse rejects `replayed`. Return the exact captured decision set only to the existing import owner. No file/SQL effect is authorized by a page/digest alone. |

Handles and application-owner authority are process-local, unguessable internal
references, never serialized into manifests, logs, URLs, recommendation fields or
session-report tokens. The future trusted presenter/transport implementation must
be separately reviewed; renderer text, an agent request, a stored manifest or an
`application` receipt alone cannot simulate the local-owner confirmation event.
An unresolved approval-owner/profile/transport capability is `Unknown`, not a
fallback dialog or assumed auth success.

Process restart revokes all review/approval handles. A retained exact manifest is
recovery evidence only: continuing after interruption requires current qualified
maintenance, exact source/progress revalidation and **fresh owner confirmation**.
No authority is reconstructed from a digest or old receipt. Cancellation after
the import owner has consumed approval cannot claim rollback of partial effects;
step 2 must specify its stop/recovery behavior before publication is implemented.

## 5. Diagnostics and remaining capability gates

Diagnostic codes are exactly: `identity-unqualified`, `backup-unqualified`,
`approval-unqualified`, `scope-unqualified`, `normalization-unqualified`,
`association-unqualified`, `history-unqualified`, `quiescence-unqualified`,
`protection-unknown`, `source-unreadable`, `enumeration-incomplete`,
`malformed-local`, `malformed-global`, `unsupported-local`, `identity-conflict`,
`unassociated`, `required-missing`, `optional-missing`, `record-too-large`,
`entry-too-large`, `path-invalid`, `alias`, `late-input`, `stale`, `replayed`,
`cancelled`, `evidence-only`, `backup-excluded`, `possible-deleted-history`.
Unknown codes reject v1. Findings are data, not instructions or deletion authority.
A failed capture returns `["las.error.v1",attemptOrNull,snapshotDigestOrNull,code]`;
null means the identity was never successfully created, not an empty successful
snapshot. This fixed-size error has no approval semantics, candidate count or
partial-success claim. Detailed path/context may be inspected only through the
owning capture's escaped diagnostic presentation, not an invented valid row.
Display error detail through escaped presentation, outside canonical machine codes;
never put credentials or raw payload bodies in report entries.

No real `known` native, backup, association/history/protection, quiescence or
trusted-application profile is qualified here. #1242/#1243/#1248/#1250 and step 2
must provide their actual closed receipts/owners. Complete aggregate storage,
pre-allocation/native path bounds and durable approval/progress recovery remain
unverified; these logical page/counter limits do not prove physical fit. No
existing linked-pair storage/probe budget can be borrowed. A complete production
approval example cannot be claimed while these capabilities are unavailable.

## 6. Independent component bytes and boundary examples

These are **encoding/framing components**, not a qualified approval witness.
They deliberately contain unknown capabilities or stub descriptors. Every such
batch is ineligible for `beginReview`/confirmation regardless of its byte size.
No product encoder/validator exists in this task. Literal array construction and
standard SHA-256 supplied the measurements; `shasum` cross-checked the small
hashes and Node independently parsed/re-encoded and measured the two byte-limit
pages. This checks arithmetic/bytes, not native paths or runtime behavior.

The following two literals have no terminating LF. `Z` below means exactly
64 ASCII `0` characters, expanded before encoding, not the letter Z:

```text
["las.session.v1","61","74"]
["las.decision.v1","0",Z,"exclude"]
```

| Component | ASCII bytes | SHA-256 |
| --- | --- | --- |
| Session for ID `a`, exact created value `t` | 28 | `53437acb966279da556609826c1cedce343078180695066337f4a8e6eae2c895` |
| Decision ordinal zero, expanded Z candidate digest | 100 | `590a76b1bdecbde492627f0281f83b93350b93c275244376b6e387d3150a67a7` |

An empty candidate-stream **component**, with Z expanded, is exactly the two
lines below, including one LF after each line:

```text
["las.header.v1","candidates",Z]
["las.end.v1","0","0"]
```

It is 121 bytes, SHA-256
`e76a628e5021fd67240a374f919c8a50c4e3d83482f2462b9b56a0a8784dabc8`.
No source snapshot/body is supplied by Z, so this stream cannot prove an empty
workspace, complete import or owner approval.

### Reconstructable complete-page framing vectors

The definitions here are value macros expanded into the exact arrays of this
contract; they do not add a wire type or production profile. `u(n)` is decimal U,
`hex(text)` is lowercase UTF-8 byte hex, and `H` is the defined hash.

- `unknown(code) = ["unknown",code]`.
- `stub(kind,n) = [kind,u(n),"0","0",Z]`; deliberately **not** a validated stream.
- `S(n) = ["las.snapshot.v1",[32 ASCII 1s,32 ASCII 2s],
  unknown("identity-unqualified"),stub("source",n),stub("global",0),
  unknown("backup-unqualified"),unknown("backup-unqualified"),
  unknown("quiescence-unqualified"),unknown("approval-unqualified")]`.
- `T(n)` is the 16-position Summary `["0","0",u(n),"0","0","0","0",u(n),
  "0","0","0","0","0","0","0","0"]`.
- `B(n) = ["las.batch.v1",H(S(n)),stub("candidates",n),stub("decisions",n),T(n)]`.
- For `0 <= i < n`, `path(i,m)` is one component equal to
  `hex("f" + decimal(i))` followed by exactly `m` repetitions of hex `61`.
  Only row zero has nonzero m in the padded cases.
- `E(i,m,k) = ["las.entry.v1",u(i),[path(i,m)],"file",
  unknown("identity-unqualified"),u(k),["sha256",rawHash(k)],null,[]]`.
  k is zero for empty bytes or ten for ten ASCII `x` bytes (row zero only).
  `rawHash(0) = e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855`;
  `rawHash(10) = fc11d6f28e59d3cc33c0b14ceb644bf0902ebd63d61218dffe9e7dac7c254542`.
- `R = ["source",u(i),H(E)]`;
  `K = ["las.candidate.v1",u(i),"evidence",R,["none"],null,"blocked",null,
  ["identity-unqualified"]]`;
  `J = ["las.decision.v1",u(i),H(K),"blocked"]`;
  the complete row triple is `[K,J,[[R,E]]]`.
- `P(n,m,k) = ["las.page.v1",B(n),S(n),"0",u(n),null,[all n row triples]]`.
  All rows other than zero use m=k=0. There is no final LF.

| Complete page component | Exact bytes | Framing-gate result | SHA-256 |
| --- | --- | --- | --- |
| P(100,0,0) | 53,754 | Row/byte bounds pass; approval remains blocked. | `58572c09fea2c7cef375eb329e3050bb67067ee297d24706b3aafc225fa0c58c` |
| P(101,0,0) | 54,291 | Reject 101 rows in one page; real pagination must return 100 then 1 without omission. | `ff04c64c42a1427af0192ce5274c18f6d697d9169ecf379f66936a12ede5e63d` |
| P(2,130143,0) | 262,144 | Inclusive byte bound passes; approval remains blocked. | `923bb63a437b9afc0797e542fcc2493f75d0796dbfb1ef59d94fcb45f2139bf9` |
| P(2,130143,10) | 262,145 | Reject the oversized page. Repack if a row can fit; otherwise entry-too-large, never truncation. | `90f94096a1b740b9a06200baaa46e65f08deb0033b85f8dce35fbcad0fd038d6` |

For n=2, the empty-file baseline is 1,858 bytes and each additional `61` adds
exactly two bytes: `1858 + 2*130143 = 262144`. Changing row zero's size from `"0"`
to `"10"` adds one byte; digest widths remain fixed. The deliberately long native
component is not a claim that any OS accepts that path. Physical/path bounds
must independently pass the qualified profile before a real eligible page exists.

### Global-only inventory inspection components

To make the completeness correction independently reconstructable, define `G(n)`
as S(n) with source stub count zero and global stub count n. Define `BG(n)` as
