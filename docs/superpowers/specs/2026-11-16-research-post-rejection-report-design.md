## Gap and preserved contracts

The [prospective membership contract](2026-11-16-research-prospective-membership-design.md#rejection-ordering-and-original-outcomes)
keeps A collecting after rejecting prospective B, retains B-derived currentInput
and explicitly leaves positive post-rejection/completion reports unclosed.
The [canonical clarification](2026-11-16-research-prospective-membership-design.md#rejection-freshness-and-profile-eligibility-clarification-—-2026-11-16)
forbids reusing its current/pending classification table after that resolution.
A null pending pointer does not prove the original B disposition or erase B's
source input. The old prefix's collecting-task/current-decision equality cannot
be restored by rolling input back or rebinding A to B's source.

The [accepted completion contract](2026-11-15-research-completion-design.md#source-owned-transition-and-effect-union)
preserves active collection after plan completion and stage cancellation. Valid
live children can still report in an active/paused run; a report changes current
input/collection and invalidates stale summary/proposal consumers without
rewriting coordination results or reopening a completed plan. Finish/run cancel
and ordinary runtime closure retain their existing cutoffs before receipt lookup.

The selected new branch closes one original collecting A and one proven rejected
B, with no new pending plan or execution/review/clarification source. It uses
existing source/request/receipt/control shapes and sole run ownership. It does
not close arbitrary reassessment, approved replacement handover, stage-cancelled
current-plan source roles, resumed child generations, terminal correction or a
full publisher. An unsupported additional consumer/state makes publication
unavailable; no false absence or implicit permission follows this selection.

## Exact original disposition and current roles

Use A for the original approved research PlanRef, TA for its reserved task,
B for its proposed replacement PlanRef and TB for B's unreserved task. The
current immutable input still contains B's configuration/scope/captures, the
exact prior-plan A entry, copied assessment provenance and zero/one selected
report from A's original stream. No current pointer is added to the collection.

Resolve all of the following from complete retained sources at the captured H:

1. Original A definition/approval/reservation/allocation/preparation/attachment,
   frozen assignment, successful original spawn and reporting RuntimeRef. Keep
   the original configuration/scope/capture and direct source/custody proofs.
   A's report evidence continues to resolve those sources, not B's captures.
2. Exact B PlanRef from run.planReferences and its original source/control,
   frozen proposed input, new configuration/scope/task and replaces=A/prior-plan
   joins. Resolve it by exact task/configuration/scope and full source identity,
   never by latest revision or an arbitrary cancelled row. Different source
   contexts remain distinguishable even when their capture contents match.
3. Original Main reject-scope-revision body/digest/key/receipt and complete
   original H/C outcome. Its request names A/B and the original captured input;
   B's cancelled control/version and false expectation/task disposition join
   that outcome. If it completed A, retain the exact paired completion key,
   scope-rejection trigger, digest/receipt/C and completed-plan control/proof.
   If it did not, prove that original non-completing outcome; an absent current
   companion is not its proof. No live predicate reconstruction is substituted.
4. run.pendingPlan is null. B is cancelled with its original disposition,
   TB remains pending/unreserved with null result, and expectation[TB] is false
   with null reservation/selectedReport. These retained values give B no report,
   approval, allocation, worktree, runtime or grant authority. False alone does
   not classify it as rejected, and no synthetic terminal task result is added.
5. collection[RunKey] is active and selects TA, whose collecting expectation
   retains its original reservation/configuration/scope and selected current
   head evidence or null. Neither original rejection nor conditional completion
   retargeted or retired it. Complete source/Stream/runtime/consumer membership
   must validate; a copied receipt, null pointer or matching edge list is not
   a source-valid prestate or proof of original ownership.

The exact selected role alternatives are:

| Alternative | Current-plan / selector relationship | Task/result and report boundary |
| --- | --- | --- |
| Rejection left A incomplete | currentPlan=A; A active/paused; completedResearchPlan null and currentSummary null in this bounded branch | TA retains its original non-complete coordination state/outcome; first or corrected A report never supplies a completed result |
| Rejection atomically completed A | currentPlan=null; A complete and selector.completedResearchPlan=A, proven by the original paired outcome | TA retains its exact reported_complete result; at least the original report required for that accepted result must be proven; later child correction changes no result/completion history |

An already completed A still does not imply the child ended. Require coherent
**current nonterminal** ordinary bridge/native ownership and still-valid reporting
authority for the selected original A runtime. Original UI turn completion can
precede ordinary child end. Do not copy an observe-terminal recovery prestate,
invent a resumed generation or infer liveness from the old spawn/report. Unknown
or closed runtime/native/commit/lease disposition denies a new report under this
branch. Ordinary stop/end remains independent and never waits on hierarchy SQL.

The run remains nonterminal: researching for the selected incomplete-plan branch
or synthesizing for the completed-plan branch, with supported blocked/paused
precedence preserved. Keep independent gates and actual parent availability. Child
reporting does not require a live parent or launch grant when its own reporting
authority remains valid. No replacement profile identifier or owner switch is
chosen: a future complete profile must recognize these roles from original
admission before this branch can be used. Old prefix/prospective/recovery bytes
are not retokened or adopted as a legal post-rejection history.

## Captured-input report transition

Support only unchanged child submitResearchReport/correctResearchReport actions
for TA's exact original stream and current generation. Use the existing complete
report body, normalized request/domain, descriptor/head/receipt/response shapes,
author and shared eight-version budget. Live expectedTaskVersion reads TA's
actual current control, never frozen assignmentVersion or an old request default.
Parent/user terminal corrections and a new runtime stream are outside this branch.

Capture/revalidate original source ownership, live authority/rate/cutoff,
run/task/collection/expectation/input/head versions, original disposition/proofs,
complete summary/source/consumer/index membership and all resource/lease/health
owners under one qualified publication boundary. New input is derived from the
**captured latest current manifest**, with no arbitrary caller list:

- Preserve its exact B configuration/scope/capture/prior-plan A records and
  copied decision unchanged. Resolve the unique original k/k parent-assessment
  row, its digest and producer/proof independently; the reporting child is the
  new event producer, never the author of a fresh B or A assessment.
- Insert first selection, or replace only TA's existing exact selected report
  source with the new accepted head/version/digest. At most this one collecting
  source is admitted. No B report, transitive excerpt fetch, configuration
  replacement or scope conversion is allowed. A's report references still bind
  A's original approved captures/excerpts and report source group.
- Advance preparation/input revisions together once through 64 and retain the
  new immutable input plus actual reporting-child RuntimeRef producer. Change
  run.currentInput and A selection/expectation/collection versions once. Keep
  B's frozen source/input, cancelled control and false expectation byte-identical.
- Do not move currentInput backwards to A's older approved input, clear its
  prior-plan entry, recreate pendingPlan, reactivate B or recycle B's task/group/
  approval identity. A fresh parent assessment and any later source proposal are
  distinct operations under their complete current-source/approval contracts.

Report publication leaves A/B plan controls, task bodies/versions/results,
ordinary bridge revisions, original rejection/completion receipts, reservation,
launch/attachment and runtime history unchanged. A remains incomplete or complete
as its original outcome establishes. The report is neither a final-condition
coordination source nor a new completion/rejection trigger. No plan/task advance,
grant creation/restoration, child ending or capacity refund is inferred.

The prospective role was removed by the original rejection. This later report
changes only actual report selection membership: increment collectionVersion
once for that selection, not again for a nonexistent prospective-role removal.
An unchanged rejected B expectation receives no expectationVersion increment.
Coalesce the sole research_run_controls.runVersion once for the complete union,
including any required summary invalidation. Exhaustion denies the entire new
mutation; no head-only acceptance, version reset or truncated consumer effects.

## Completed-plan summary invalidation

In the completed-A alternative, selector.currentSummary is either null or an
exact currently selected ResearchSummaryRef S. If nonnull, resolve its full
ResearchSummaryV1/body/digest, original parent/input/report provenance, direct
origin and complete current/historical source membership. Unknown required review
or another completed plan/input context is unavailable, not treated as empty.

| Before report | Required report outcome |
| --- | --- |
| currentSummary null | Preserve the selector byte-for-byte if no other owned field changes; no invented selector rewrite or summary version |
| currentSummary S bound to captured input/report | Clear currentSummary atomically before new head/current input is visible; retain summaryVersion high-water, completedResearchPlan=A and all original S bytes/origins/history |

The report does not allocate a new summary version, recreate a summary, clear
completedResearchPlan, change finishDisposition/pendingStageContinue, or rewrite
S's original source/digest. The summary high-water stays at its original value
even at 64. A later original summary publication is separately authorized and
must obey its own current-input/report/review/parent and next-version limits.
Returning an old summary publication receipt never reselects S or proves it is
current. Current detail/viewing cannot mark a stale retained summary as displayed
current material through receipt lookup alone.

Preserve the selected run state and raw blocker/clarification/stage/pause gates;
losing a summary pointer alone does not finish/reopen a plan, assess the new
input or approve execution. Selected positive cases have no pending proposal,
execution approval/reservation, review/clarification source or additional active
preparation requiring an unsupported transition. Any actual broader dependent
consumer requires its full owning invalidation/fencing effects or denies the
whole publication. Never serve an old passing #744/#745/#746/cache/detail source
as current merely because its immutable bytes remain retained.

## Exact retries, races and closure

For original report retries, current child authority/generation/runtime/run
closure and rate checks precede original normalized request/receipt/proof lookup.
An identical accepted request returns its original closed response and original
input/control/summary outcome before live CAS, without new input, summary
invalidation, version, source, role, event or charge. Changed original bindings
conflict; missing/conflicting original outcome/proofs are unavailable. Do not
rebuild the old response or expectedTaskVersion from today's task/head/input.

The original Main rejection retry still resolves its original exact request/
receipts and any paired completion after fresh Main lookup authority checks.
It does not adopt the later input/report as its rejected source, recreate a
pending pointer, overwrite the original C or reevaluate completion against live
state. An original proved non-completing rejection does not borrow a later
completion merely because it names A. These two retry authorities stay distinct.

An already captured report must revalidate if rejection, ordinary lifecycle,
input/summary publication, stage/runtime change or another report wins first.
Report-after-rejection is a new captured source context, not patching an occupied
request/decision identity. A parent reassessment or new proposal winning first
may move currentInput outside this selected B-derived branch: deny the stale
capture and require that new context's complete owner, never roll it back to B.
Unrecognized pending/approved/execution consumers deny rather than disappear.

If report advancement wins against a version-bound finish action showing S,
that stale finish capture/input/summary fails and requires fresh current display.
If finish/run cancel wins first, the run is terminal and child reporting is
revoked before original receipt lookup under its existing cutoff. No terminal
absorption bypass, admission-first late save or #744 claim-first exception is
selected. Original transaction/native uncertainty retains its sole owner,
protected leases/worktree and capacity until proven; timeout/transport abort
cannot assert rollback or authorize another worker. Nonblocking stop/end and
source/authority/commit serialization remain independent qualification gates.

## Read/write, discovery and accounting boundary

The complete actual read union includes original run/bootstrap, A/B definitions
and controls, all original source/input/assessment/producer/custody references,
original rejection/optional completion/read snapshots/direct proofs, TA/TB and
reservation/launch/attachment/current ordinary bridge/runtime, collection/all
expectations and derived role/Stream indexes, authoritative report/head/receipt
history, selector/S/history, all #744–#746 consumers/summary caches and current
resource/lease/health/index/physical owners. Include zero-reference, historical,
cancelled and tombstoned owners; none can be inferred absent from pendingPlan=null.

Local represented writes are the new report/head/original receipt, immutable new
input/producer, A expectation selectedReport/version, collectionVersion, sole run
input/version, and selector only when S is cleared. Every actual resource,
custody/summary/source/index/header/new-proof effect remains additional and
mandatory, not an optional side job. B/TA/TB/source/disposition/plan/ordinary
history rows are retained reads, not rewritten to make the new outcome fit.
Only a complete qualified publisher can bind all effects to one actual C.

Derive both directions from the current input's exact B-context source records
and original A prior-plan/collection/Stream joins, plus B's proved original
rejection disposition and any original completion. Discover every current and
historical input/summary/report consumer, not just direct current citations.
An inactive pointer or cancelled plan does not erase retained source consumption.
Stable complete owner/index generations and cumulative discovery limits must
hold at final validation; matching edge tuples alone prove no completeness.

Keep all existing source/input/report/control/receipt domains, keys, projections,
caps and counters. New input/source/report occurrences pay their existing exact
resources; selector/collection/run/expectation replacements coalesce full
original-to-final deltas once, without a sharing discount or refund for retained
summary/history. Copied original H/origins/proofs stay charged. No new resource
name, zero-ledger repair, counter election or delayed initializer is introduced.

Preserve 32 KiB/256-record inputs, 64 preparation/input revisions, 64 summary
versions, report eight-version budget, source/receipt/row/snapshot limits, shared
8 MiB/run and 64 MiB/workspace source/control pools and 32 MiB run aggregate,
smaller paired-job/ordinary ceiling, 4,096 changed rows/16 MiB command and shared
discovery/physical/scratch bounds. A required new input beyond 64 denies the
whole report, while a current-authorized original retry remains read-only.
Summary invalidation needs no new summary version, even if that counter is full.
No finite component total can qualify whole-command/job/store fit.

No family/schema/profile identifier or physical format is added here. Candidate
57 logical names and admission counts 28/25 stay conditional, not complete or
maximal. Existing initializer and old profile fixtures are not modified or
adopted; full original owner selection, bidirectional index/initializer/direct
proof/authority/native/ordinary participation and physical history remain open.
