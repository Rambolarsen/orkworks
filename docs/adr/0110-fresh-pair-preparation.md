# Fresh paired storage seeds the complete original preparation profile

- Status: accepted for further qualification; implementation/activation gated
- Deciders: owner, scoped “keep going” decision on 2026-11-06
- Date: 2026-11-06
- Tracking: [#1445](https://github.com/Rambolarsen/orkworks/issues/1445), [#1176](https://github.com/Rambolarsen/orkworks/issues/1176)
- Canonical contract: [fresh pair preparation acceptance](../superpowers/specs/2026-11-05-fresh-pair-preparation-design.md#scoped-contract-acceptance--2026-11-06)

## Context

The accepted child/artifact/control profile requires four workspace resource keys beyond
the older nine-resource workspace initializer. Original attachment cannot create
missing shared ledgers or infer its upstream root/parent/allocation events from
source bytes. The accepted paired storage, permit, membership and RegistryRoot
directions therefore need an explicit fresh seed and original path contract.

## Decision

Use the exact contract reviewed in #1441 at
`c0ef79db803d74a145339f1b4579b42b01170bdb`, merged
`b7d77329edcb6bc023e7c7b1af77c27b6ab0b969`, for further qualification.
Initialize only a genuinely new owned format6/schema2 pair with all thirteen
specified workspace keys and complete physical correspondence. Keep initial
creation separate from root draft/admission. Seed root/run resources and initial
run control at their specified original owning events; all required shared peer
keys precede child commands and are never filled in on a missing-row lookup.

Use the first-parent-only parent-runtime-attach classification and the supported
original direct-execution proposal, approval, reservation, distinct allocation
begin/outcome and complete child-source-attach path. Preserve frozen identity,
private actual-owner inputs, exact H/G/read sets, version/effect/charge rules and
original proven/unknown disposition. Only the already accepted original-child
permit may finish that exact paired unstarted save after later volatile close;
other commands retain strict source cutoffs.

## Consequences

Fresh creation can leave an unavailable original failed/unknown attempt; it cannot
adopt an existing file, recreate a missing peer, unburn namespace reservations or
restore a grant. Historical goldens and prior initial-only packets remain intact.
These choices complete the selected next contract without superseding ADRs
0106–0109 or permitting a second profile inferred from missing rows.

Actual fresh/native/ordinary/source/runtime/UI/grant/allocator owners, strict
physical source cutoffs, physical membership and feasible hard resource/recovery
bounds remain required evidence. The bounded prior design review is reused for
unchanged definitions; no runtime or qualification result is inferred.
No product code, SQL/DDL/database/schema/migration, dependent fixture, recovery
scan, executable/native plan, model/native probe, live capability, new quota/bearer
or activation is authorized. #1176 stays open; #740 stays closed research.
