# Fresh-pair evidence inventory for evaluation publication

This is the first profile inventory for the
[evaluation publication evidence contract](../superpowers/specs/2026-11-27-evaluation-publication-witness-design.md)
under [#1176](https://github.com/Rambolarsen/orkworks/issues/1176).
The inspection is pinned to `2c32c3b1f433073b6130bb305b1d1406e9374d41`.
The candidate is one genuinely new hierarchy format 6 and ordinary schema 2
pair in one workspace. Its accepted seed and original-child preparation sequence
provide a starting point for tracing the initial evaluation write. The other two
evaluation operations use the same packet requirements and need their own exact
effect evidence. Gate 2 remains **Investigate**.

## Next written checkpoint

Trace the initial write from the accepted original child preparation path
through its first evaluation admission. For each required logical key, identify
the existing owning representation and direct proof path in the candidate pair.
Record any unavailable owner, key, compatibility rule or cost at the point where
the trace stops. This is the smallest trace that can expose a gap between the
accepted format-4 producer commitments and the candidate physical catalog
without assuming a new command tag, codec or migration.

This inventory records available source and contract evidence. It establishes no
qualified pair or full-state packet. Any executable fixture, storage operation or
native qualification run requires its own authorized scope. The separate
[Windows live-reader proposal](https://github.com/Rambolarsen/orkworks/pull/2222)
remains outside this inventory.
