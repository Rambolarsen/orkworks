# Offline research configuration and startup components

Tracking: [#1689](https://github.com/Rambolarsen/orkworks/issues/1689) and
[#1089](https://github.com/Rambolarsen/orkworks/issues/1089).
Inspection base: `a2fa4a765190d89011c688b6a59e5229a6c1e3ca`.

This continues the owner's [scoped source acceptance](../superpowers/specs/2026-11-12-research-source-codecs-design.md#scoped-owner-acceptance-and-first-component-packet)
and [capture/scope packet](research-capture-scope-components.md). It adds a
complete synthetic OutputAssignmentConfiguration v3, retained common capability
artifacts and exact declared startup. It qualifies source shapes and byte joins
only. Actual admission, capture origin, approved plan/group, model delivery,
logical-tool mapping and native authority remain unqualified. Gate 2 stays
Investigate. No runtime/native execution is performed.

## Independent packet and common-leaf reuse

- [Python generator](https://github.com/Rambolarsen/orkworks/blob/main/docs/validation/generate-research-startup.py) constructs the research role, permission profiles, manifests, settings, model policy, unverified capability evidence, source hashes and framing independently of JavaScript.
- [Retained packet](research-startup-components.json) contains context, configuration, evidenceObjects, captures, scope and declaredStartup. This wrapper is test packaging, not a persistence/protocol type.
- [Checker](research-startup-components.mjs) composes existing common validators with explicit research profile, startup and source joins. It reuses the accepted child instruction renderer without modifying direct-execution validation.
- [Tests](research-startup-components.test.mjs) compare independent regenerated bytes, check semantic mutations after resealing and exercise composed-startup capacity.

The generator reads the unchanged child-source packet only for its synthetic
run, repository/worktree descriptors, rule/skill/resource/rubric leaves and
executable/platform shapes. The capture/scope packet supplies sample text and
questions. It constructs new research task bindings and source hashes; it copies
no approval, prepared input, reservation, control, attachment, receipt or report
history. Reused instruction provenance remains synthetic. A newly hashed role
or evidence body does not upgrade those sources to actual native evidence.

The context supplies a complete synthetic run plus group ID, base commit and
registered object-format assumption. The existing run checker verifies its
closed fields, digest and admission-epoch/sequence spelling. Configuration owner,
repository, worktree, group/base and capture/scope keys must join exactly. The
original run/group/native producer and future plan are not reconstructed by
this check. No ParentPlanBinding or prepared-input codec is invented.

The record checker accepts already decoded objects. Stored canonical component
bytes must first pass the capture/scope packet's canonical byte decoder; ordinary
JSON.parse alone cannot preserve duplicate-member evidence. Retained settings,
effective-configuration and model-policy artifact bytes pass the existing strict
canonical decoder inside this checker. The human-readable packet wrapper itself
does not claim a canonical storage encoding.

## Exact selected configuration and delivery

The source uses unchanged schemaVersion 3, the
`orkworks.assignment-configuration.v3` digest, child instruction header/boundary,
assignment block and rule/role/skill/resource ordering. No scope field is added
to the configuration. Settings bind the prior scopeDigest, avoiding a digest
cycle. The research specialization requires:

- role research; empty assignment inputs/dependencies and read/write paths;
- empty output declarations and zero snapshot/rehash allowances; reviewInput null;
- exactly the three accepted logical research report tools in both profiles;
- no command, path, external-source, connector, coordination, native-delegation or automatic-access grant;
- complete mandatory-skill/manifests/resource/provenance and harness/model/evidence joins;
- exactly one research-input immediately after the supplied entry, with every automatic instruction retained in discovery order.

The supplied frame is followed by LF, `ORKWORKS RETAINED RESEARCH INPUT v1`, LF,
canonical decimal UTF-8 payload byte length, LF, canonical `{scope,captures}`, LF.
Full ordered captures are included. Automatic instructions may occur before or
after the supplied/data pair under the existing order contract. The complete
startup, not just the supplied frame, must fit 256 KiB. Storage-valid larger
sources are denied rather than truncated or fetched later.

The retained oracle measures independently:

| Quantity | UTF-8 bytes |
| --- | ---: |
| Complete canonical configuration | 11,695 |
| Complete composed startup | 5,110 |
| Raw retained capability-evidence occurrences | 1,288 |
| Raw file-capture occurrences | 29 |

These are source measurements, not object-row charges or total store usage.
All evidence occurrences are measured, including identical content under separate
reference IDs; zero-byte non-settings evidence remains an occurrence. Capability
decision is unverified and all retained oracle surface results are unverified.
The logical report IDs issue no ResearchReportCapability and prove no adapter
eligibility, transport, containment or successful tool use.

failed. Final tests cover direct-execution/root role substitution, live access
and foreign tools, missing report tools, inline input, dependency/output/review
variants, owner/group/base/repository aliases, manifest/mandatory-skill errors,
verified evidence assertions and unknown configuration fields. Settings cases

unlisted/omitted automatic content and wrong discovery digests. Evidence tests
cover occurrence closure, task/length/Base64 bindings, model disagreement,
duplicate settings JSON members, harness mismatch, changed instruction framing,
omitted/misspelled composed data and the unchanged configuration digest domain.

An independently grown role payload makes the complete startup exactly 262,144
bytes, including changed decimal frame-width digits, and passes. One additional
byte is denied while its supplied frame alone still fits 256 KiB.
The 1 MiB configuration and 64 KiB artifact checks remain in force; this packet
does not claim boundary witnesses for every reused common-leaf maximum. All
original common component tests remain in the documentation suite.
