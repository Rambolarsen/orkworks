## Artifacts and explicit assumptions

- [Independent Python generator](https://github.com/Rambolarsen/orkworks/blob/main/docs/validation/generate-research-scope-rejection.py) builds new synthetic sources and decoded decisions using canonical bytes and the existing offline instruction renderer; it never invokes JavaScript.
- [UTF-8/LF JSON oracle](research-scope-rejection-components.json) retains one new unapproved proposal and two separate rejection alternatives.
- [Finite JavaScript checker](research-scope-rejection-components.mjs) independently validates complete startup/source joins, original decisions/receipts, versioned after-values, ordered submissions and occurrence measurements.
- [Component tests](research-scope-rejection-components.test.mjs) exercise semantic mutations, supplied-fact retry, revision exhaustion and containing limits.

The unchanged prefix and continuation JSON are raw-byte fingerprinted inputs.
The current original plan/reservation/approval, root/bootstrap/repository/custody,
turn and coordination identities come from those source bytes. They are neither
replayed nor elected into a current store. The new revision-2 configuration,
capture/scope/evidence/startup and plan are constructed separately, preserving
the complete retained-file source grammar. Their hashes establish internal byte
relationships, not original authority, actual event provenance or model delivery.

The singleton RunKey collection cannot acquire a second active task or retarget
the reserved original task. Reserved-current-plan proposal membership/publication
is still unclosed. No collection/expectation rows are invented here. Their complete
prospective/current/historical memberships and retirement/invalidation effects
are **stipulated, unqualified facts**, not established by a pending pointer.
This packet therefore supplies no legal positive pending prestate, full effect
union, source-valid publisher/store or history.

Main/current parent authentication, exact shown source, rate, scope/workspace/epoch/
owner/lease/health, native/ordinary settlement/capacity, report/review eligibility,
complete source/consumer membership, original command/outcome/direct proofs and
actual H/C are supplied and unqualified. The paused-parent, stage-continue,
clarification, review and execution variants are not exercised. No check of a
label makes that label authoritative.

## Prior-plan input and rejected proposal source

The new proposal remains in the same run/planId at revision 2, with a distinct
taskId/configurationId/worktree group. Its complete ResearchSourcePlanV1 binds
the new revision-3 prepared input; that input contains exactly one prior-plan
record naming original approved revision 1. The existing configuration/scope/
capture records remain complete and UTF-8 sorted. The new decision is a fresh
research-only assessment at revision 3; it is not a reporting child rewriting
the old assessment. No approval/reservation/allocation/runtime is created for
the new proposed task.

The captured pending plan has status proposed/version 1, latestApproval null
and replaces equal to that original prior-plan input entry. Its task stays
pending/version 1, reservation/result null. Both rejection alternatives retain
the proposed task unchanged and mark only its plan cancelled/version 2. No task
is repurposed for a later approved attempt, and no rejected source is deleted.

An ordered retained submission example [approved revision 1, rejected revision 2]
requires the next changed proposal at 3. The finite helper validates the supplied
complete original-owned order, duplicate/missing/out-of-order denials and the
64-revision cap. It does not discover history, select a largest version or recover
missing references. Changed future proposals still need fresh exact source/input
and approval under their separately qualified owner; this helper grants nothing.

## Retry, denials and widths

The pure retry oracle checks supplied current Main/context/rate/owner facts and
original complete source/membership/disposition/outcome facts before original
lookup. Indexed/hashed/receipt keys and both receipts' resulting versions are
checked against the captured original decision, never today's live versions.
Identical original request bytes resolve the original receipt, and the
original paired completion when the supplied original outcome completed. Later
terminal run labels, advanced live versions or current rows cannot recreate or
change that outcome. A non-completing original requires original absence proof
as a supplied obligation, not absence of a live row. Missing/conflicting companion,
unknown proof/disposition, revoked authority and changed request deny; no new write.
The fixture-only originalOutcomes map separately binds each rejection digest to
its supplied original C and completion digest or explicit null. It is outside
all accepted bodies/digests/catalogs and supplies no actual proof. Changing a case
label or removing its companion cannot elect the non-completing branch.

Decision mutations are rehashed and remeasured before validation, so semantic
joins must catch stale versions/H, changed trigger/ref, candidate-as-prestate,
rewritten task results, double increments and lost independent blockers/history.
Source mutations additionally exercise exact prior-plan/input/source digests,
proposed approval/replaces, distinct task/group and complete startup relationships.
The checker recognizes these finite alternatives; it is not a general wire
decoder, credential/lease validator, race scheduler, lifecycle reducer or store.

The checker applies existing startup/source and 32 KiB input/64 KiB plan limits,
2 MiB decision wrapper/4 KiB receipt, 1 MiB run/16 KiB named plan/task/selector
snapshots, and the smaller 1 MiB paired-job necessary bound. A width-only padding
test fits individual wrappers but exceeds the joint ceiling and rejects; it is

4,096-row/16 MiB command limits remain independent and binding. Necessary small

## Review and verification disposition

evidence/denial completeness. Both identified that the standalone retry helper
did not fully bind receipt/indexed keys and resulting versions. Seven focused
regressions failed before the fix; the helper now checks exact original request/
body/indexed/receipt keys, original captured resulting versions and the complete
paired completion body. A boundary regression also failed before correcting an
overstrict guard: a non-completing rejection does not increment the current
plan, so its unchanged version may already be at the ceiling. No second static
review round or additional native/source qualification is claimed.

review are recorded with the PR. Earlier packaging/semantic and rate/owner tests
failed before implementation. A case-label-only branch denial failed before
adding the external original-outcome correspondence. The oracle's decision bytes
and occurrence charges were unchanged by the review fixes. All 569 prior
non-Markdown validation artifacts remain byte-identical; source design is
append-only. Docs/index/render/link, OKF and close-out checks provide only the
stated offline evidence. Product/native/full-repository verification is not run
under the no-runtime constraint, and no broad success is claimed. Existing bundler
notices and another owner's stale worktree require no unrelated change. Task
worktree reporting succeeded; primary lockfile residue remains untouched.
