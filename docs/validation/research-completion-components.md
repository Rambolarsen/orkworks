## Completion, synthesis and invalidation alternatives

The positive completion binds the original completed coordination request/digest/
receipt and reported_complete task to a new lifecycle decision. Its captured run
version is 11, resulting version 12, plan version 2→3 with status complete and
run state synthesizing. The source coordination/task advance and completion share
symbolic C only as a supplied compound-outcome requirement; old partial source
origins are not rewritten to pretend this packet proves that transaction.

The full typed pre-trigger run/plan/selector snapshots and H are retained. The
selector selects the exact completed plan. Same-parent planning remains selected;
the exact plan grant must be revoked, children remain ordinary capacity holders,
and the run collection remains active. These latter effect labels are contractual
obligations, not executed native events or complete mutation/proof evidence.

The second trigger has the accepted recovery union shape and resolves the original
observe-terminal recovery decision. Its candidate task is still needs_parent_result;
therefore it has **no completion row**. A recovery digest is not a completed task.
No positive final-condition recovery source is fabricated. The accepted obligation
to complete atomically on a genuinely eligible recovery remains; that source/outcome
and broader scope-resolution trigger codecs still need separate closure before
positive history/writer qualification. Unsupported triggers deny their entire
transition; they cannot postpone completion to a new manual step.

Two independent summary examples use output versions 1 and 2, an 8 KiB body,
exact completed plan/current input/parent/report provenance, empty review refs
under the explicit no-required-review assumption, and distinct source digests.
They are derived outputs, not new current-input records or execution permission.
All three prose lists have independent 16-entry limits and individual prose fields
have 2 KiB limits; the whole body and 128 combined-reference ceilings still win.
The finite checker accepts only these examples; it is not a general summary codec.

The summary helper checks supplied current authority/rate/stage-gate facts before
exact-key retry lookup. Identical original summary bytes return their historical
ref/proof before live CAS, without reselecting currentSummary; expectedRunVersion
is an admission precondition, not retained identity. New keys need current run
version, exact high-water+1 and room through 64. It does not discover missing keys,
authenticate a parent, prove coverage or publish anything. The invalidation view
clears only currentSummary and retains high-water 2 and both immutable sources.
Actual report/input changes and all dependent consumer invalidations remain one
complete source-owned outcome, not supplied by this isolated view.

## Main UI alternatives and precedence

Three finish examples preserve the exact research-only, no-go and
declined-execution dispositions. They require a current valid summary and no
execution proposal/approval/allocation/reservation; broad proposal invalidation
is unavailable until its source codec is closed. They set research state complete,
clear parent/current/pending plan pointers and retain summary/history. Finish does
not grade the task or claim goal acceptance.

Stage cancellation marks the exact plan cancelled/version+1, keeps a live parent
with read/wait/result-only rights, preserves a native-disposition blocker and
records paused/stage_cancelled with an exact pending cancellation ref. Continue
clears only that gate/ref, keeps the blocker and selects blocked; it restores no
grant, task or reservation. Runtime resume alone cannot clear the stage gate.
The supplied-fact helper also tests interrupted-parent resume, unsettled attempts,
unsupported clarification and terminal absorption. It runs no actual resume.

Run cancellation keeps an unknown-attempt blocker, raw true stage gate and
historical cancellation/summary refs, revokes automation and clears parent/plan
pointers. Common-control paused-only fields become null after leaving paused;
preserving raw gates does not mean retaining pauseReason/resumeTarget on a terminal
body. Child capacity/native ownership stay held until their actual ordinary owner
resolves them. Terminal collection retirement, closed waits, all grant/report
revocations and unknown-outcome fencing are mandatory effect labels, not proofs
or a child-kill/rollback/retry implementation.

The UI retry helper checks supplied current Main authority and exact shown context
before original request lookup, then returns the original receipt without live
CAS even after terminal state. Changed request bytes conflict. It authenticates
no context/generation/lease and is neither an endpoint nor a complete admission
function. Unknown store disposition yields unavailable/reconciling, never an
invented successful receipt, replacement worker or timeout rollback. No new late
permit, child cutoff, terminal correction or TerminalReportRunV1 cast is supplied.
